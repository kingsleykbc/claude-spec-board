# Milestone 1: Core File Format Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `@specboard/core`, a tested TypeScript library that loads a project's `.specboard/` folder into typed objects, works out blocked/dependents/progress, and changes files surgically (only the bytes that need changing) with conflict detection.

**Architecture:** The library is pure functions over strings (`parse*`, `set*`), plus a thin file-system layer (`loadProject`, `writeIfUnchanged`, `createSpec`, …). Front matter is parsed and edited with the `yaml` package's Document API, which keeps comments and formatting. The Markdown body is handled with a small line-based section parser, not a full Markdown AST, so that unchanged lines stay byte-identical. The M2 server and the M3 Claude plugin both build on this library.

**Tech Stack:** Node ≥ 22, TypeScript (strict, ESM), npm workspaces, `yaml` ^2, Vitest.

**Spec:** [`docs/documentation.md`](../../documentation.md), especially §6 (file format) and §7 (two-way sync). Roadmap: [2026-11-08-roadmap.md](2026-11-08-roadmap.md).

## Global Constraints

- No database. The files under `.specboard/` (plus linked reference files) are the only source of truth.
- UI writes are surgical: an edit changes only the targeted lines. Every other byte, including line endings, stays identical (§7).
- Every write carries the base content hash. If the file changed on disk, the write is refused with the current content. Nothing is silently overwritten (§7).
- The parser tolerates small manual mistakes and reports them as `problems`. It never throws out of `loadProject` (§6).
- Windows 11 is a first-class platform: CRLF files, `\` paths, and rename-over-existing must all work.
- Status values: `todo | doing | review | done`. Urgency: `low | normal | high | urgent`, default `normal`.
- IDs are `T-` plus at least 3 digits (`T-001`). The next ID is the highest existing ID across `specs/` and `archive/`, plus 1.
- Blocked is never stored. It's worked out from unanswered questions and unfinished dependencies. Dependents are never stored either.
- The repo root is `C:\Users\Kingsley\Desktop\Projects\claude-spec-board`. All paths below are relative to it.

## File format (pinned by this plan; refines doc §6)

```
.specboard/
  config.md                     # front matter: name, references (string[] of repo-relative paths); body = project description
  overview.md                   # front matter: updated (ISO datetime); body = progress summary
  specs/<ID>-<slug>/spec.md
  specs/<ID>-<slug>/logs/<n>-<slug>.md
  archive/<ID>-<slug>/…         # same layout
```

**`spec.md` front matter keys:** `id`, `title`, `status`, `urgency`, `categories` (string[]), `depends_on` (string[]), `draft` (bool, default false), `current_subtask` (number | null: the subtask Claude is working on right now), `created`, `updated` (YYYY-MM-DD).

**Body sections:** `## Spec`, `## Features`, `## Open questions`, `## Subtasks`. Headings are matched case-insensitively. Any other section is kept untouched.

**Open question line:**
`- [ ] Q<k> (<type>[: opt1 | opt2 …]): <text>`, followed by an indented answer line `  > answer: <value>`.
- `type` is one of `yesno | number | text | choice`.
- `choice` lists its options after the colon.
- A question counts as answered when its answer value is non-empty after trimming.
- The writer keeps the checkbox in step: `[x]` when answered.

**Subtask line:** `- [ ] <n>. <title>` (`[x]` when done).

**Log file `logs/<n>-<slug>.md`:**
- front matter: `subtask` (n), `commit` (short hash or empty), `files` (string[])
- body: entries headed `### <YYYY-MM-DD HH:mm>`, each followed by free text

## Review Focus

1. **CRLF files** (written on Windows): every `set*` edit keeps `\r\n` on every line, including the lines it changed. Tests are in Task 3.
2. **A hand-edited, malformed spec** (broken YAML, unknown status, missing `## Subtasks`, a garbled question line): it loads with `problems` filled in and safe defaults, and the other specs load normally. Tests are in Tasks 2 and 5.
3. **A file changed on disk between read and write** (e.g. Claude writes mid-edit): the write returns `{ ok: false, conflict: true, currentText }` and the file is unchanged. Tests are in Task 6.
4. **A dependency on a missing ID, a self-dependency, or a cycle:**
   - no crash and no infinite loop
   - a missing dependency blocks the spec with the reason `"T-999 not found"`
   - an archived dependency counts as done

   Tests are in Task 5.
5. **Titles with symbols or non-ASCII** (`Search & filters`, `Café menu`, `A/B test: "v2"?`): the slug is lowercase ASCII `[a-z0-9-]`, at most 40 characters, and valid as a Windows folder name. An empty slug falls back to `spec`. Tests are in Task 6.
