# Spec Board: Roadmap

**Spec:** [`docs/documentation.md`](../../documentation.md). The visual design is in [`docs/design/`](../../design/).

The design is too big for one plan. It's built in four milestones. Each one ends in working, tested software, and gets its own detailed plan, written once the previous milestone has landed so it can use the real interfaces.

| # | Milestone | Ends with | Plan |
|---|---|---|---|
| 1 | **Core: file format** | `@specboard/core`, a tested library that reads, derives and surgically edits `.specboard/` files, plus the Recipe Box sample project | [2026-11-08-m1-core.md](2026-11-08-m1-core.md) |
| 2 | **Server + board** | `npx specboard` opens the board on the sample project. It shows live updates from disk and writes UI edits back. | written after M1 |
| 3 | **Claude integration** | The Claude Code plugin (commands + skill), `init` with the allow-list, and the Run/Stop button with streamed output | written after M2 |
| 4 | **Ship** | Playwright end-to-end tests, CI, README with GIF, final name, npm publish | written after M3 |

## Milestone 2 scope (for planning later)
- **Server:** a Hono server and the CLI entry point (`specboard [path]`), which picks a free port and opens the browser. It also keeps the project registry in `~/.specboard/projects.json`.
- **REST + WebSocket:**
  - `GET /api/projects`
  - `GET /api/project` (the full `Project` from core)
  - mutation endpoints, which wrap core's edit functions and send the base `hash` with every write. A changed file returns `409` plus the current file.
  - a WebSocket that pushes `project-changed` events. The server watches files with chokidar and debounces changes.
- **Web:**
  - React + Vite, built from the prototype in `docs/design/`, with its CSS tokens copied as they are (Geist fonts, light and dark themes).
  - Storybook, with stories for every component state in the prototype (card states, run states, empty states, light and dark), run as tests through Storybook's Vitest integration. Server and component tests use Vitest.
  - Board: filter bar, drag and drop with dnd-kit, archive, and Done reachable only by a human move.
  - Card detail: section editor with preview, questions, dependencies, subtasks, and the log view.
  - Overview (counts, summary, Export .md), References (tabs, edit, link, create in `docs/`, remove), Add spec, project switcher.
  - Toasts, the conflict dialog, live-change highlights, and the connection indicator.
- The Claude-triggering buttons (Run, "Have Claude write this up", "Ask Claude to fix", Refresh summary) are shown but call a stub until M3.

## Milestone 3 scope
- **Plugin:** a Claude Code plugin with `/create-spec`, `/update-spec`, `/run-spec`, `/next`, `/refresh-overview`, `/refresh-logs`, `/correct-specs`, plus a skill that teaches the file format and its rules (doc §8).
- **`specboard init`:**
  - creates `.specboard/`
  - writes the conservative allow-list into `.claude/settings.json`, merging with what's already there, after showing it and asking the user to confirm
  - installs the commands
- **Run manager:**
  - one run per project
  - spawns `claude -p "/run-spec <id>" --output-format stream-json` in the project root
  - streams events to the card over the WebSocket
  - Stop kills the process tree. That needs care on Windows; use `tree-kill` or `taskkill /T`.
  - detects the end states: finished, needs answer, permission denied, and error
  - if `claude` isn't on the PATH, falls back to copying the command
- Wires up the buttons that were stubs in M2.

## Milestone 4 scope
- Publish as an **open-source, public repository on Kingsley's GitHub account** (not GitLab), with LICENSE (MIT), CONTRIBUTING.md, and issue and pull-request templates. Creating the repo and pushing to it are done only with Kingsley's go-ahead.
- Playwright end-to-end tests on the main flows, and GitHub Actions CI on Windows and Ubuntu.
- Pick the final name, avoiding "Claude" in it (doc §12).
- README with a GIF and screenshots, publish to npm, and a demo with the sample project.
