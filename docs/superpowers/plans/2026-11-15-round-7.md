# Round 7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the 12 round-7 changes: header and footer polish, images in Markdown, inline Markdown on cards, popups that open on hover, a More info section in the logs, answered questions shown as text, clickable toast paths, Save/Cancel moved to the bottom, and flagging or refreshing stale questions after a spec edit.

**Architecture:** Mostly `packages/web` (React 19, Tailwind v4, shadcn/Radix, story-based tests). There are a few small additions elsewhere:
- core: the `needs_refresh` front matter field;
- server: the image route, the flag set on body save, and the `refresh-questions` run kind;
- one new plugin skill.

**Tech Stack:** TypeScript, React 19, Vite 7, Tailwind v4, Radix, react-markdown + remark-gfm, Hono (server), Vitest + RTL + `composeStories`, Storybook.

**Spec:** `docs/superpowers/specs/2026-11-15-round-7-design.md`. Read it. It is the authority, and its "Calls made after the builder check" section settles the edge cases.

## Global Constraints

**Layout and tests**
- Component layout stays the round-6 way: kebab-case folders, each holding `<name>.tsx`, `<name>.stories.tsx` and `<name>.test.tsx`.
- Component tests render stories via `composeStories`.
- No barrel files.
- No CSS modules. Use Tailwind only, plus inline styles for runtime values only.

**Icons and breakpoints**
- Icons come from `react-icons/lu` through `packages/web/src/lib/icons.ts`.
- The narrow breakpoint stays `useNarrow` (≤720px).

**Tests to run**
- `npm test` (all workspaces) and `npm run test:stories -w @specboard/web` must pass.
- `npx tsc -p packages/web/tsconfig.json --noEmit` must be clean.

**Commits**
- Never add `Co-Authored-By` or any Claude/AI attribution lines.
- Never touch `git stash@{0}`.

**Safety**
- Never use `git worktree`, junctions or symlinks.
- Never force or recursively delete outside `.superpowers/`.
- Never use interactive git (`-i`, `-p`).
- If a command is refused, stop and report. Don't work around it.

**Fixed values from the spec**
- Exact copy: "These may be out of date after the last spec edit. Run `/specboard:refresh-questions <ID>` in Claude."
- Front matter key: `needs_refresh: YYYY-MM-DD`. Core parses it as `needsRefresh: string | null`.
- Image extensions: `png jpg jpeg gif webp svg avif`.
- Image route: `GET /api/projects/:pid/image?path=<project-relative path>`.
- New run kind: `refresh-questions`. Its prompt is `/specboard:refresh-questions <ID> --board`.

## Review Focus

These are the cases most likely to bite real use.

**Images**
1. A traversal, absolute or UNC path, or a non-image extension sent to the image route gets 400 or 404 and never the file bytes. **Task 5 tests this.**
2. Image paths with spaces or URL-encoded characters (`images/my%20shot.png`, `images/my shot.png`) load. A reference in `docs/sub/x.md` resolves `../img/a.png` to `docs/img/a.png`. **Task 5 tests this.**

**Flagging after a spec edit**
3. Saving the spec body of a Review or Done spec, or a draft, never writes `needs_refresh` and never starts a run. **Task 8 tests the server side and Task 9 tests the client side.**
4. Adding or removing `needs_refresh` leaves every other front matter line byte-identical, including CRLF files. **Task 8 tests this.**

**Questions**
5. In the questions editor, pressing Edit on one answered question and then Cancel restores the saved answer and leaves other questions' drafts alone. **Task 7 tests this.**

### Task 5: Images in Markdown (item 5)

**Files:**
- Create: `packages/server/src/routes/images.ts` and mount it in `packages/server/src/app.ts`
- Test: `packages/server/src/routes/images.test.ts` (follow the neighbouring route tests' setup)
- Modify: `packages/web/src/components/ui/markdown/markdown.tsx`, adding a `baseDir` prop and an image renderer
- Create: `packages/web/src/lib/image-src.ts` + `image-src.test.ts`
- Modify callers:
  - `spec-section.tsx`: `baseDir` = the spec's folder, project-relative, archive-aware. Use the `Spec.dir` / `path` the web view model already has, made project-relative.
  - `references-modal.tsx`: `baseDir` = `dirname(reference path)`.
  - `docs-page.tsx`: none.
  - `logs-modal`, `overview-modal`, `sync-dialog`: none.
- Docs:
  - `docs/guide/` (the page about writing specs by hand) says: "put a spec's images in its `images/` subfolder and link them relatively, e.g. `![Login screen](images/login.png)`".
  - Add the same rule to `plugin/skills/specboard/SKILL.md` (layout), `plugin/skills/create-spec/SKILL.md` and `plugin/skills/update-spec/SKILL.md`.

**Interfaces:**
- Server: `GET /api/projects/:pid/image?path=<rel>`.
  - Resolve with `safeProjectFile(entry.root, rel)`. It must accept `.specboard/...`; check this and allow it if needed.
  - The lowercased extension must be in `png jpg jpeg gif webp svg avif`, otherwise 400.
  - A missing file gives 404.
  - The response sets `Content-Type` from the extension (`image/svg+xml` for svg), `X-Content-Type-Options: nosniff`, and `Cache-Control: no-cache`. Svg also gets `Content-Security-Policy: sandbox`.
  - An unknown pid gives the same error the other routes give.
- Web: `imageSrc(pid: string, src: string, baseDir?: string): { kind: 'img'; url: string } | { kind: 'link'; url: string }`.
  - `http:` and `https:` give `img` as-is.
  - Relative paths with a `baseDir` are joined with posix normalisation, `decodeURIComponent` is applied once, and the result is `img` with `/api/projects/${pid}/image?path=${encodeURIComponent(joined)}`.
  - A relative path without a `baseDir`, a path that escapes the root after normalising, or any other scheme (`data:`, `file:`, …) gives `link` with the original src.
- `Markdown` props add `baseDir?: string`.
  - The pid comes from the existing project context or hook the app uses. If there is none, add an optional `pid` prop and pass it from callers.
  - An `img` result renders `<img src alt loading="lazy" className="max-w-full rounded-lg border border-line">`.
  - A `link` result renders the old `🖼 alt` link.

  - `spec.md` gives 400.
  - A missing `images/none.png` gives 404.
  - An svg response has the `sandbox` CSP and `nosniff`.

### Task 7: Answered questions as text; read-only in Review and Done (item 9)

**Interfaces:**
- Add a prop `readOnly: boolean`. The caller (`card-detail.tsx`) passes `spec.status === 'review' || spec.status === 'done'`.
- Each question is in one of three modes:
  - **view:** it has a saved answer and is not being edited. It shows the answer as plain text, plus an "Edit" button when `!readOnly`.
